## Problem
Each client used a different specification for collecting review data, which drove up operating costs. LLM API costs for the summarization pipeline were also high.

## Approach
We established the EP (Engine Paper) specification and API schema as a shared contract, then redesigned the prompt structure with cost efficiency as the priority.

## Execution
- Defined a shared EP format for review and product data and documented the client onboarding guide
- Reworked the API schema around client usage scenarios to simplify operating policies
- Shifted the summarization workload from primarily GPT-4o to primarily 4o-mini
- Consolidated the 2-prompt processing path into 1 prompt to reduce token costs further

## Results
- Completed delivery to 2 clients (현대홈쇼핑 and 쇼핑엔티)
- Moved the existing summarization workload from primarily GPT-4o to primarily 4o-mini to optimize its cost structure
- Consolidating the request flow into 1 prompt reduced both operating complexity and cost
